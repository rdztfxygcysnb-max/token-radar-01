How implied value is computed

Base multiple
Each category carries its own multiple — the median market-cap-to-TVL ratio of live-token peers in that category. A category with too few peers falls back to the global median. The multiple is the category’s, never a single protocol’s.
Growth
Seven-day TVL change, clamped to the model’s floor and cap, then weighted. Fast-growing TVL earns a higher multiple; shrinking TVL earns less.
Maturity
Time since the protocol was first listed — the best record of how long it has run with no token. Older protocols score closer to the full maturity factor; an unlisted age uses the model’s fallback age.
Chains
Each extra chain beyond the first adds a small premium, capped, for protocols that have already spread across chains.

Every row is scored by the same function of the snapshot figures. No protocol name is special-cased and no row is hand-picked. TVL, growth and age come from the snapshot alone; there is no hand-kept list of names.

Conservatism note. The multiples use circulating market cap, not fully-diluted value, so they understate what a token would be worth on a fully-diluted basis. The board is deliberately low, not generous.

How the model is calibrated

Each category’s base multiple is the median market-cap-to-TVL multiple of its live-token peers — protocols whose token already trades. Categories with too few peers use the global median instead, marked below. This is where the board visibly separates protocols whose token already trades from those still to come: the live set teaches the model, the pre-token set is scored by it.
